# Body at 10 fps, YOLO11n-seg and precise body — Shorts, 2026-10-12

Coverage is now **Face / Body / Precise body / Frame**. Face is unchanged and stays the default.
Body samples at 10 fps on face mode's grid (it decoded and detected every frame) and uses
YOLO11n-seg boxes. Precise body covers each person's silhouette from the same model.
Reference behaviour: iOS `51b2459` and `aff74c2`.

Clip: [How I fake having a cameraman](https://youtube.com/shorts/rX6wXhLqOIQ), H.264 + AAC copy,
53.3 s, 1,598 frames. Every run: **Women**, blur 60, **NSFW off**. Runs are the real app via the
debug autorun hook, benchmark build, installed as the isolated `com.haithamassoli.naqi.bodyqa`
package (`-PnaqiBenchmarkSuffix=.bodyqa`). Raw logs, EDLs, outputs and frame grabs:
`qa-assets/bench-out/body-10fps/` (gitignored).

## Coverage against the every-frame YOLO26n body EDL

`scripts/bench/compare_edl.py` evaluates both EDLs per frame like `Edl.kt` on a 90×160 grid.
Mean covered area: before **0.585**, after body **0.723**, after precise **0.620**. Body covers
pixels the old EDL covered and the new one does not on 333 of 1,598 frames. Almost all of those
lose less than 2% of the frame at a box edge. The rest were checked frame by frame:

- 2.2 s, 3.8 s, 17.9 s, 48.3 s: the old run blurred the whole frame and the new one covers the
  person's box. Only comment text or background is left clear.
- 21.1 s, 21.5 s, 22.3 s: a person on the camera display; the new box covers the display.
- **35.2–35.3 s: tiny pedestrians on a street corner stay visible in body mode. Not fixed.** The old
  run blurred the whole frame for 5 frames (35.15–35.32 s) after one lucky face hit and left the
  same pedestrians visible for the rest of the 32.3–35.5 s shot. YOLO11n-seg boxes some of them
  (more than YOLO26n did at 32.5 s). The rest are ~20 px tall in a 360×640 analysis frame.
  Covering them needs detection on source-resolution crops, at roughly twice the analysis time on
  this clip. In the final precise run a face hit blurred the whole frame there.

Precise body leaves background clear by design (711 frames lose pixels). The worst frames were
checked for exposed people: hands, passers-by at 22.5 s and 23.5 s, and the camera displays stay
covered. A 90°-rotated copy of 22–28 s renders the same silhouettes as the upright run.

## Findings fixed while testing

1. At 10 fps a person on the camera display (7.33–9.8 s, 15.3 s) and comment avatars (6.4 s) were
   only found on some samples and stayed visible between them. Tracks now keep a missed person's
   box for 900 ms (the nine misses every-frame mode tolerated as 300 ms). Anyone first found within
   1 s of a cut is covered from the cut. Orphan-face whole-frame spans run from just after the
   previous sample. 7.4 s, which the old every-frame run also left visible, is now covered.
2. iOS's crop retry on empty samples was tried. At Android's 640 px analysis frames it found nobody
   new (947 people either way) and raised S23 analysis from 74 s to 135 s, so it is not used.
3. "Precise body" / "الجسم بدقة" clipped in the four-way row; the labels are "Precise" / "بدقة".

UI: `qa-assets/bench-out/body-10fps/ui/coverage-row.jpg` (English precise, Arabic precise and body).

## Model

YOLO11n-seg, the checkpoint iOS screens (SHA-256 `55ed65c5…dcbe152`), ONNX FP32, opset 17,
static 640, `ultralytics==8.4.171`, export timestamp stripped: `a119f46d…6ba758c41`, reproduced by
two exports. Parity on ultralytics' bus/zidane images: same 4 and 2 people as PyTorch and as
ultralytics' own post-processing, boxes/scores within 6.1e-5, all 32-cell mask cells equal, and
95.3% of cells matching ultralytics' upsampled masks (the decoder samples prototype cells).

Precise EDLs store one 32-cell bitmask per observed sample: 281 KB for this clip (body: 79 KB,
before: 178 KB).

## Reproduce on a Galaxy S23

```sh
./scripts/fetch-models.sh
./gradlew :app:assembleBenchmark -PnaqiBenchmarkSuffix=.bodyqa
export ANDROID_SERIAL=<S23 serial>
PKG=com.haithamassoli.naqi.bodyqa
adb install -r app/build/outputs/apk/benchmark/app-benchmark.apk
adb shell pm grant $PKG android.permission.READ_MEDIA_VIDEO
adb push qa-assets/bench-out/body-shorts/rX6wXhLqOIQ/input.mp4 /sdcard/Download/body-input.mp4
# one run per mode; omit the last extra for Face, use --ez body_blur true for Body
adb logcat -c
adb shell am start -n $PKG/com.haithamassoli.naqi.MainActivity \
  --es autorun_path /sdcard/Download/body-input.mp4 --es censor_who women --ez censor_nsfw false \
  --ez body_precise true
adb logcat -s JobStats:I | grep -m1 'SOAK total'      # analyze/render/total lines
adb pull /sdcard/Android/data/$PKG/files/bench/last-edl.json
.venv-bench/bin/python scripts/bench/compare_edl.py before-edl.json last-edl.json
```

Let the battery cool to ~32 °C between runs; a warm phone throttles.
